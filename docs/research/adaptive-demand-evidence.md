# Adaptive demand: evidence, decisions and remaining native proof

Planning decision: **2026-10-07 (Europe/Berlin)**. This research supports the
[forecast plan](../../openspec/changes/forecast-01-local-adaptive-demand/proposal.md),
not a claim of delivered prediction accuracy. See [product behavior](../forecasting.md).

## Research cross-check

SciSpace and Consensus were searched on 2026-10-06. Relevant Consensus records were
retrieved before use; primary papers were checked rather than accepting portal
summaries or duplicate records as independent replication. Scite rejected access
because its account lacked a paid plan/active trial; citation-support/contradiction
analysis was not performed. Only generic research questions were submitted, not
repository contents, session logs or private account data. This was a targeted
cross-check, not an exhaustive systematic review.

| Primary evidence | Finding and practical boundary |
| --- | --- |
| [Bai et al., v3](https://arxiv.org/html/2604.22750v3), rechecked 2026-10-07 | Eight-model SWE-bench study: difficulty and usage differ; self-predictions underestimate and remain noisy. Assessment itself consumes resources. Supports testing coarse signals, not authoritative LLM token guesses. |
| [ACEM, v2](https://arxiv.org/abs/2608.02582), rechecked 2026-10-07 | Proposed context/revision/oversight structure leaves coefficients symbolic pending calibration. No validated complexity-to-token mapping can be imported from it. |
| [Task-demand profiling, v1](https://arxiv.org/html/2609.01271v1), rechecked 2026-10-07 | Spread/novelty/centrality describe reference patches. Useful dimensions, but completed patches are future information for initial forecasts. |
| [Smékal, v1](https://arxiv.org/html/2608.25399v1), accessed 2026-10-06 | Specification/reasoning conditions matter in a limited five-task/one-model study. Improved forecast results use an executed target-task probe, not cost-free preassessment. |
| [Tokenomics](https://arxiv.org/abs/2601.14470), accessed 2026-10-06 | Review dominated consumption in a preliminary 30-task ChatDev/GPT-5 setup; do not adopt its proportions as universal factors. |
| [Production Copilot traces](https://arxiv.org/abs/2608.00101), accessed 2026-10-06 | Autonomous loops, context reuse and variable usage justify separate execution qualifiers; privileged production telemetry is not an MVP requirement. |
| [Instruction-file study](https://arxiv.org/abs/2601.20404) and [context-file evaluation, v3](https://arxiv.org/abs/2602.11988), accessed 2026-10-06 | Different setups report different efficiency directions. Instruction presence cannot receive a fixed universal discount. |

Most directly relevant items are recent preprints or preliminary studies. These
papers do not establish that ChangeCost's chosen dimensions, transfer or rehearsal
improve ordinary local-user forecasts. Chronological local evaluation is required.

## Exact remaining evidence requests

1. **Codex:** matched native request/snapshot records and parent/child boundaries
   for the same interval, stable response identity, correction/resume/reset examples,
   cache categories, final boundary and all-attempt coverage. Version separately.
2. **Claude:** repeated/revised message groups with associated request/result
   identity, version-specific precedence, cache inclusion, result/transcript overlap,
   terminal coverage and subagent ownership. Keep estimated costs separate.
3. **Copilot:** reconcile root/direct/turn/checkpoint/session boundaries with native
   identity, cumulative replay/reset/correction and cache inclusion. Separate CLI,
   Local IDE and hosted SDK evidence. Shutdown alone does not prove completeness.
4. **Cursor:** existing native consumption evidence if available, otherwise retain
   its metadata-only/unverified lane. Optional personal CSV needs actual headers,
   rows, tier/version, range/timezone, identity and included/on-demand meanings.
   No upgrade, collector or paid request is required to manufacture support.
5. **Transfer:** actual matched complete tasks in older/newer ecosystems, frozen
   task/implementation baseline, changed settings and outcome population, plus
   cutoff availability and compatible measurement semantics. No such bridge or
   validation is claimed by this planning batch.
6. **Optional custom hook:** sanitized mapping code or paired native/upload and
   receiver-transform evidence. Missing hook proof is a separate capability gap.

## Confidence, risks and rollback

High confidence in observed repository boundaries and the explicit planning
decisions; medium confidence in usable version-specific aggregation/transfer;
forecast benefit remains unvalidated. Source retention, hidden model alias changes,
partial subagent coverage and task drift can change conclusions.

Duplicate accounting -> independently reviewed identity/revision lanes. Misleading
transfer -> explicit hypotheses and chronological baseline comparison. Leakage ->
frozen initial inputs and independent truth cutoffs. No paid infrastructure is
required; native proof controls timing. Rollback is a scoped planning revert,
preserving originals, archives and review history.
